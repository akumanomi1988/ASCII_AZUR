# Android APK build and release gate

## Engineering contract
- Source: unchanged TypeScript modules and static assets generated by
  `npm run build`; native `MainActivity` only hosts the local app.
- ABI: standard Android Java/WebView; min API 26; JDK17, AGP 8.8.2,
  Gradle 8.10.2, compile/target API 35, WebKit AndroidX 1.12.1.
- Build artifact: `android/app/build/outputs/apk/debug/app-debug.apk`.
- Check provenance: `assets/package-info.json.main_sha256` must equal
  `sha256sum dist/main.js`, and versions must match.
- Android WebView retains original WebGL2/Canvas2D selection; native FPS requires real physical-device measurements.
- No user data to external endpoints; app origin is private to APK, so
  PWA/browser data **must be exported/imported** when migrating.
- No Android release keystore in source; NEVER sign commercial artifacts with
  the debug key or report a signed Android release from a debug APK.

## Automated Android emulator gate
1. Build the actual APK using Gradle after `tools/stage-android-assets.py`.
2. Install debug APK on both API 30 and API 35 emulators; launch native Activity.
3. Verify native WebView loads assets from the bundled HTTPS origin with no
   failed resource requests, JS exceptions or remote HTTP requests.
4. Use Android native OS touch to start a new game, select a starter, and
   verify a real save exists. Force-stop and relaunch in airplane mode;
   verify the same save and seed are present.
5. Rotate portrait/landscape and exercise a real native touch game control.
   Validate native file picker and Android Storage Access Framework export.
6. Retain APK build SHA-256 and Android emulator diagnostics. Emulator evidence
   is NOT physical device acceptance.

## External release signoff
- Owner nominates lowest-supported physical phone and checks G4/U2/A3.
- Confirm user-directed export/import between installed Chrome PWA and Android.
- Real Play/app-store signing, data disclosures, company identity and any
  distribution fees require separate explicit authorization.
- Keep `docs/AAA_ROADMAP.md` 21/32 (68.75%) until its **existing**
  independent/hardware acceptance criteria are observed. The new APK does not
  substitute any human signoff.

## Native save import round-trip gate

A complete native transfer is accepted only when Android Files opens through the real app import button, the test selects a synthetic `save-v1` document from Downloads, the native overwrite confirmation is displayed, the player approves it, and localStorage contains the validated imported record after the app's existing optimistic-save transaction. It must preserve world seed and creature identity; an invalid or canceled import must never overwrite a player's progress. No private storage injection, JS handler direct invocation, or network upload may substitute for this acceptance.

The API 30 native acceptance branch uses a document **created by the game's own Android `ACTION_CREATE_DOCUMENT` picker** and reselects it via `ACTION_OPEN_DOCUMENT`, avoiding unindexed ADB-pushed scoped-storage fixtures. API 35 separately imports a different valid v1 fixture to verify overwrite semantics. Both require a user-visible native confirmation and a successful application save transaction.
